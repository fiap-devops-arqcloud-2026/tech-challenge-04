Baixo nível 4 — o caminho da telemetria

O OTel Collector roda em dois modos, instalados como duas releases do mesmo chart (opentelemetry-collector, que exige escolher mode e a imagem). O agent é um DaemonSet: um pod por nó, que lê do disco os logs de todos os contêineres daquele nó. O gateway é um Deployment central: recebe os traces dos serviços e os logs dos agents, processa e decide o destino.

Por que cada escolha

O conector spanmetrics faz três requisitos com um sinal só. Ele conta os spans por serviço e por status.code e mede a duração — as métricas de taxa, erro e latência. Daí saem o painel de taxa de requisições (REQ-OBR-10b) e a expressão da regra de alerta (REQ-OBR-16), sem uma linha de métrica escrita nos serviços. O README do conector dá os nomes traces.span.metrics.calls e traces.span.metrics.duration, com as dimensões service.name, span.name, span.kind e status.code. O nome exato depois da conversão para o Prometheus fica para conferir na E3 — o próprio README mostra um exemplo com calls_total. O conector está marcado como alpha.

O Prometheus não aceita escrita por padrão. No chart kube-prometheus-stack (versão 91.5.0 na data da consulta), prometheus.prometheusSpec.enableRemoteWriteReceiver vem false. Precisa ser ligado, senão o exporter do gateway recebe erro. Existe também enableOTLPReceiver, igualmente desligado — alternativa válida, mas o remote write é o caminho que o README do spanmetrics documenta.

O Loki recebe OTLP nativo. A documentação do Loki manda usar o exporter otlphttp com endpoint: http://<loki-addr>/otlp e exige allow_structured_metadata: true, que já é o padrão a partir do Loki 3.0.

O New Relic recebe só traces (e, opcionalmente, os logs do togglemaster). Ele calcula sozinho as métricas de APM a partir dos spans; mandar também as do spanmetrics duplicaria dados e gastaria a cota de 100 GB/mês. Endpoint US: otlp.nr-data.net, portas 4317 e 4318, header api-key com a license key — conferidos na documentação oficial.

O Alertmanager pode ser desligado. Ele vem ligado por padrão no chart, mas a regra de alerta vai morar no Grafana. Desligar com alertmanager.enabled: false economiza memória num cluster apertado.
