Arquitetura de alto nível

Cinco camadas, lidas de cima para baixo como uma história: o código chega ao cluster, roda, relata o que faz, os relatos viram painéis e, quando algo quebra, o sistema reage. A mesma convenção de cores vale para todos os diagramas deste documento:

Como ler, camada por camada

Entrega. Você faz push. O GitHub Actions compila, testa e escaneia. Só na main ele constrói a imagem, envia ao ECR e comita a nova tag no próprio repositório. Nada disso muda na Fase 4.

Execução. O ArgoCD não recebe aviso: ele consulta o repositório a cada 30 segundos (timeout.reconciliation = 30s em terraform/k8s/argocd.tf) e aplica o que mudou. Os nós puxam a imagem do ECR. O que muda: os serviços passam a carregar instrumentação, e o ArgoCD passa a gerenciar também a stack de observabilidade.

Telemetria. É o coração da Fase 4. Todo sinal passa pelo OTel Collector, que decide o destino: métricas para o Prometheus, logs para o Loki, traces para o New Relic. É esse roteamento que o vídeo precisa explicar (REQ-OBR-26d) e o relatório precisa descrever (REQ-OBR-39).

Visualização. O Grafana consulta o Prometheus (linguagem PromQL) e o Loki (LogQL). O New Relic tem painel próprio, onde ficam o Service Map e o trace distribuído.

Resposta. A regra de alerta vive no Grafana. Ao disparar, três destinos recebem a notificação ao mesmo tempo: o PagerDuty abre o incidente, o Slack recebe a mensagem e o GitHub Actions executa a correção.
